## Recently completed (2026-07-26)

- **Prestávka per služba per terapeut (FSS :189, MS :859).** Only half of this existed: `services.break_minutes`, one value per service, invisible everywhere except the slot engine — and applied to a whole day from whichever service was being booked. The break now belongs to the therapist: `staff_profiles.break_blocks` is their default, `service_therapists.break_blocks` (nullable = inherit) overrides it per assignment, both counted in reservation blocks per the spec's wording. The pivot gained a surrogate `id` so it could become a repeater on the service form; the therapist's profile shows their default plus a read-only resolved summary. `GapFiller` now carries a break per busy interval instead of one scalar — which also fixes a latent bug where a category mixing breaks computed the wrong anchor after an existing booking. Reservations freeze the break they were booked with (`reservations.break_minutes`, set by `ReservationObserver`), so changing a default never reshapes existing bookings; that snapshot is what the calendar's grey „Pauza" strip and the new break-inclusive „Do" column render. Existing assignments were backfilled from their service's old value, so behaviour was unchanged on the day it shipped.

- **B7. ✅ Done (2026-07-18)** — Payments / Invoices / Substitute-Tokens tabs added to the admin client. See "Recently completed".
- **B18. Storno fees + payment-deadline auto-cancel for enrollments (owner request, 2026-07-26 — DEFERRED, discuss later).** One-time lessons (`OneOffEvent`/`LessonBooking`) — and possibly course series (`CourseEnrollment`) — should carry a **storno fee** on late cancellation, and unpaid spots should **auto-cancel X days before series/lesson start** and be re-offered to the waitlist. Distinct from B9 (that closed reservation auto-storno; this is enrollments).
  - **Manual-payment reconciliation is not a blocker.** No gateway exists (QR/bank transfer recorded by hand via `RecordPaymentAction`), but the flow is already driven off the *recorded* payment: `PaymentObserver::handlePaid` → `PayableSettlement::settle` (forward-only paid flip, never reverts) → `CloseOverInvitedLosers::afterPayment` already cancels over-invited losers and frees the spot. "Payment = irreversible confirmation + spot goes to whoever pays first" already works today.
  - **What actually needs building:**
    1. **Deadline shift.** Today the unpaid hold is a flat *48h after signup* (`Settings::enrollmentHoldHours` → `due_at`, swept by `ExpiredPaymentHold` / `enrollments:cancel-unpaid`). Owner wants it keyed to *X days before start*. Change the `due_at` computation (`SignUpForOffer.php:156`, `OfferSpotToEntry.php:68`) and the sweep query (`ExpiredPaymentHold.php`).
    2. **Bank-transfer lag — the real design point.** A hard cancel exactly at the deadline risks killing someone whose transfer is in-flight (1–2 business days to clear + manual recording delay). Needs either a **grace buffer** between the customer-facing due date and the actual sweep (and never cancel after the event started), or an **owner-reviewed suggestion** (reuse the Návrhy/Suggestions subsystem) instead of an automatic cron kill.
    3. **Storno fee = retain-from-paid, refund the rest by hand.** Inverse of reservations (which *charge* an unpaid fee, since they're not prepaid). A prepaid lesson: on late cancel, retain the fee and compute `refund = amount_paid − storno_fee`; owner pays it back manually (consistent with the existing "refunds settled by hand" model in `CancelSignup`). Implies the fee only applies **after** payment is recorded — unpaid = never confirmed = free cancel / silent auto-cancel, nothing to retain.
  - **Open decisions for the later discussion:** (a) fee scope — one-time lessons only, or course series too; (b) confirm fee applies only to already-paid cancellations; (c) auto-cancel = automatic-with-grace vs. owner-reviewed suggestion; (d) fee amount = percentage of price (reuse a `stornoFeePercent`-style setting) vs. flat per-event field. Also: what the client self-cancel window (`CancelSignupAsClient`, `courseCancelBeforeDays`/`eventCancelBeforeHours`) becomes — a hard cutoff, or "cancel allowed but fee applies" like reservations.
